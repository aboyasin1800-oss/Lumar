# عقد التنفيذ المختصر: RL-6-POINTS-SETTINGS-REDESIGN-02

## الحالة

هذا عقد تنفيذ مقترح بعد تدقيق قراءة فقط. لا يبدأ التنفيذ البرمجي ولا تعديل الجداول قبل اعتماد هذا العقد والحقول الجديدة صراحة.

## النطاق المعتمد

### مركز إعدادات الولاء والنقاط

شاشة رئيسية للتنقل فقط، تعرض:

- حالة البرنامج العامة.
- وقت آخر تحديث.
- رابط إعدادات البرنامج العامة.
- رابط نقاط قطع منتجاتنا.
- رابط نقاط أصناف المبيعات المستوردة.
- رابط قواعد الولاء.
- رابط مستويات كبار العملاء.
- رابط إعدادات الإحالات.
- تنبيهات صادرة من Backend للأنواع والأصناف غير المضبوطة.

لا تعرض الشاشة الرئيسية قوائم كاملة أو تقارير أو أكواد TRK.

### إعدادات البرنامج العامة

تنفذ فقط الحقول الحالية المعتمدة:

- `IsEnabled`
- `PointsPerPiece`
- `PointMonetaryValue`
- `EffectiveFromUtc` عند الحاجة للعرض أو التعديل وفق العقد الحالي.

أما الحقول التالية فتظل معلقة حتى عقد مستقل:

- الحد الأدنى والأقصى للاستبدال.
- السماح بالكسب.
- السماح بالاستبدال.
- الإنذار والانتهاء والمصادرة.

### نقاط قطع منتجاتنا

المصدر: `PricingProductTypes` عبر إدارة القياسات.

المفتاح المطلوب: `ProductTypeId`.

يشترط قبل التنفيذ إضافة عقد ربط يربط إعداد النقاط بـ`ProductTypeId`. لا يستخدم الاسم أو TRK أو Barcode أو كود قطعة منفردة كمفتاح بديل.

تقرأ الشاشة كل الأنواع الفعالة من المصدر، وتطابقها مع إعدادات النقاط من Backend. النوع بلا إعداد يظهر بحالة "يحتاج تحديد نقاط".

### نقاط الأصناف المستوردة

المصدر: `ImportedReadyMadeProducts`.

المفتاح المطلوب: `ImportedReadyMadeProductId`.

يشترط قبل التنفيذ توفير عقد وإعدادات Backend خاصة بنقاط المستورد. لا ينشأ صنف من شاشة النقاط، ولا يستخدم رقم البيع أو الحركة أو Barcode الفردي كهوية إعداد.

### الشاشات المستقلة

- قواعد الولاء: قراءة وإدارة ما يدعمه Backend فقط، دون تفعيل محرك القواعد تلقائيًا.
- مستويات كبار العملاء: قراءة وإدارة الحقول المدعومة فقط، دون تطبيق Multiplier على المحرك.
- إعدادات الإحالات: قراءة وإدارة التعريفات المدعومة فقط، دون تعديل الحركات أو الشجرة أو النسب غير المحفوظة.

## عقد الحقول المطلوبة قبل التنفيذ

يلزم اعتماد Backend للحقول التالية:

1. `ProductTypeId` في إعداد نقاط منتجاتنا.
2. `ImportedReadyMadeProductId` في إعداد نقاط المستورد.
3. حقول برنامج الولاء الإضافية إن كانت مطلوبة.
4. عقد سلوك النوع أو الصنف غير المضبوط: fallback الحالي إلى `PointsPerPiece` أو عدم منح نقاط.
5. عقد الصلاحية والمصادرة والمهمة المجدولة ونوع الحركة التاريخية.
6. عقد إشعارات الأنواع والأصناف غير المضبوطة الصادرة من Backend.

## سلوك fallback الحالي

حتى يصدر قرار مستقل، يبقى السلوك الحالي كما هو: النوع الذي لا يملك إعدادًا فعّالًا يستخدم `PointsPerPiece` العام عبر محرك النقاط الحالي.

لا يتم تغييره بصمت.

## عقد الصلاحية المقترح للمراجعة

لا ينفذ في هذه المهمة قبل اعتماد مستقل. يجب أن يحدد لاحقًا:

- حدث بدء العد: آخر شراء أم آخر نشاط ولاء.
- الفرق بين انتهاء الصلاحية والمصادرة.
- نوع حركة المصادرة.
- منع التكرار.
- إعادة بدء العد عند شراء جديد.
- معالجة النقاط المكتسبة في تواريخ مختلفة.
- طريقة تشغيل المهمة المجدولة.

## ممنوعات هذا العقد

- لا Migration قبل موافقة صريحة.
- لا تعديل مخطط.
- لا مصدر أنواع موازٍ.
- لا مصدر مستورد موازٍ.
- لا تعديل تاريخي.
- لا تشغيل تلقائي للقواعد أو VIP أو الإحالات.
- لا استخدام TRK أو TrackingCode كمفتاح إعداد.

## ترتيب التنفيذ بعد الاعتماد

1. اعتماد عقد الربط والحقول المعلقة.
2. تنفيذ مركز التنقل.
3. تنفيذ إعدادات البرنامج الحالية.
4. تنفيذ ربط أنواع منتجاتنا بالمصدر الرسمي.
5. تنفيذ ربط أصناف المستورد بالمصدر الرسمي.
6. تنفيذ تنبيهات Backend.
7. ربط الشاشات المستقلة.
8. اختبار التفعيل والتعطيل وإعادة القراءة.
9. البناء والتحليل والتقرير.

## حالة العقد

بانتظار اعتماد صريح للحقول والعقود الجديدة قبل أي تعديل Backend أو Flutter أو قاعدة بيانات.
