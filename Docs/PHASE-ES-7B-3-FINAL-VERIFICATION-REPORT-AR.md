## 1. سبب الإغلاق المبكر

## 2. دورة إنشاء المورد

- أضيف عقد إنشاء رسمي للحقول الموجودة في `dbo.Suppliers` فقط.
- أضيف التحقق والصلاحية `Purchasing.Manage` وخدمة ومستودع كتابة واتصال تشغيلي.
- يستمد المنفذ من جلسة Bearer ولا يقبل هوية من المستخدم.
- يسجل النجاح عبر `Es7OperationalAudit`.
- يمنع تكرار `SupplierCode` داخل معاملة `Serializable` وقفل تطبيق transaction-scoped للرمز.
- أضيف نموذج عربي وزر إضافة وبحث وتحديث فوري للقائمة.

## 4. الدفعات

## 12. المانع والمخاطر المتبقية

أول رابط غير مكتمل هو:

`Supplier invoice header -> SupplierInvoiceLines API -> receipt line selection -> invoice matching differences`

يوجد جدول ومحرك `SupplierInvoiceLines`، لكن لا يوجد عقد API معتمد لإنشاء أو قراءة بنود فاتورة المورد، ونموذج الفاتورة الحالي ينشئ الرأس والمبلغ الإجمالي فقط. لذلك يستطيع المستخدم مطابقة الاستلام مع أمر الشراء وعرض فروقه، لكنه لا يستطيع تنفيذ مطابقة بنود الفاتورة من الواجهة. إصلاح ذلك يتطلب إضافة عقد أعمال وAPI لبنود الفاتورة، وهو تغيير عقد معتمد يحتاج موافقة مالك مستقلة حسب السياسة.
